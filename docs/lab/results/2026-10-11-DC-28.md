# DC-28: DDI provenance and reboot (W4; run in W9, 2026-10-11)

- **Check:** `tests/lab/dc28-ddi.sh` with `RUSSET_DC28_FORCE=owner-approved` (decisions.md Q33: one reboot and the
  replacement of the mirror DDI approved for W9). No pymobiledevice3 on `PATH` (the script removes `~/.local/bin`
  and checks).
- **Commit tested:** `a5ea275` (the forced mount), then `3ad83bd` for the DC-05 runs on the same DDI.
- **Result: passed (gate item 7).** `russet device ddi status --json`:
  `{"kind":"cryptex1","mounted":true,"productBuild":"27A266a","source":"dir","version":"27.1.266.1"}`, and the
  script's `demo/m1-russet.sh` run stopped at the RussetProbe breakpoint (35.4 s, `probeValue = 42`).

## What happened

1. **Reboot** (10:41:20Z, `idevicediagnostics restart`, the one approved reboot). The phone re-enumerated on USB
   after about 45 s and was paired and usable without waiting (tunnel up at the first poll).
2. **The mirror DDI survived the reboot.** Status right after it: `cryptex1`, `27.1.5228.8`, `productBuild
   27A5228h`, `source: unknown`. pymobiledevice3 had installed it with `persistence 2` (persistent), like Xcode, so
   `device prepare` correctly left it alone (a mounted DDI is a no-op).
3. **First forced mount failed** (commit `733154f`): Russet's `--force` personalized the 27A266a cryptex with TSS and
   called cryptexd `install` over the mounted one; cryptexd refused:
   `device.ddiPersonalizationFailed` (3010), `cryptexd install: system: cryptex already exists`
   (`com.apple.security.cryptex` 17). The phone kept 27A5228h; nothing else changed.
4. **Fix** (`a5ea275`): with `--force`, Russet personalizes first (so a TSS failure never leaves the phone without a
   DDI), then cryptexd `uninstall`s the installed `com.apple.MobileAsset.DDI` cryptex (identifier + version from
   `copy-installed`), then installs. cryptexd accepted the uninstall of the persistent mirror cryptex and the
   install of the Apple-origin 27A266a copy; Russet wrote its mount record (`state/devices/<udid>/ddi.json`,
   `source: dir`).
5. **Launch and debug on that DDI**: DC-28's own `demo/m1-russet.sh` run and the three DC-05 runs all passed.

## Notes for W10 (DC-29)

- The 27A266a cryptex is installed persistently too, so it is expected to survive the next reboot; DC-29's

- The 3010 hint for cryptexd domain `com.apple.security.cryptex` code 17 talks about the network and TSS; "already
  exists" deserves its own hint (W10).
